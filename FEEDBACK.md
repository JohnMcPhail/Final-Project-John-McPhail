# FEEDBACK

This feedback is organized by the grading categories you listed: repo organization, data, script, README, and visualizations. It also includes additional comments and an overall summary.

## Repo Organization

**What’s strong**

- The project has a clear scientific goal (Matnog vs Sacol vertebra shape comparison).
- The raw input folders were present and the analysis intent was clear from filenames and text.

**What needed improvement**

- The original repo was “flat” (most things in the top level) and did not follow the recommended `data/raw`, `data/processed`, `scripts`, `results` layout.
- OS/editor artifacts were committed (`.RData`, `.Rhistory`, `*:Zone.Identifier`), which creates noise and hurts reproducibility.

**What was fixed (so the project matches expectations)**

- Raw inputs now live under `data/raw/`.
- Code lives under `scripts/`.
- Outputs go to `results/` and `data/processed/`.

## Data (Raw vs Preprocessed)

**What’s strong**

- You are using genuinely “analysis-relevant” raw inputs for the morphometrics workflow: TPS landmark coordinate files.
- The dataset is your own/collected (not a tiny toy dataset), which is good for the assignment’s intent.

**What to clarify/improve**

- TPS landmark files are already the product of an upstream manual/interactive step (landmarking). They are “raw for this analysis”, but they are not raw *from the instrument*.
- The README should explicitly describe the upstream landmarking step (what software, what landmarks, who did it, and whether landmarks were validated/repeatable).
- Add a short metadata description: number of specimens used per group, what “Back.TPS” represents, and any exclusion rules.

## Script (Style + How Much It Had To Be Altered To Work)

**What’s strong**

- The analytical workflow is appropriate for the question (GPA → PCA → mean shapes → allometry correction → permutation tests).

**Issues that impacted reproducibility**

- The original script required RStudio (`rstudioapi::getActiveDocumentContext()`), so `Rscript ...` failed from the command line.
- The original report/code included hard-coded absolute Windows paths (non-portable).
- The original console “results” were hard-coded text (“p ≈ ...”) rather than being computed from the model output.
- Figures were created interactively but not written to files, which makes it harder to verify outputs without running an interactive R session.

**What was fixed**

- The pipeline now runs from the repo root with `Rscript scripts/run_morphometrics.R`.
- Inputs/outputs are parameterized and use repo-relative paths by default.
- P-values/R² in `results/summary.txt` come from the models that are actually run.
- Figures are saved automatically into `results/figures/`.

## README.md

**What’s strong**

- The original README had a thorough explanation of the biological question and a clear workflow narrative.

**What to improve**

- A README for a reproducible repo must include: how to run, what gets created, and where outputs go.
- Avoid listing numerical results in the README unless they are generated by the code or clearly labeled as example output; otherwise they can become stale.

**What was fixed**

- The README now includes repo structure, how to run the pipeline, requirements, and output locations.

## Visualizations

**What’s strong**

- You included multiple relevant visualizations for morphometrics:
  - PCA (PC1 vs PC2) with group separation
  - mean shape overlays (raw and allometry-corrected)
  - within-group variation (boxplot of distances)

**What to improve**

- Add clear figure captions (what the reader should conclude).
- Consider adding sample sizes to plots/legends (e.g., `n=...` per group).
- Consider exporting a PCA scores table and/or using a consistent plotting style (base is fine, ggplot is optional).

## Additional Comments

- The analysis currently uses only `*_Back.TPS` files. If other views exist (e.g., dorsal/front), document why “Back” is the focus and/or extend the pipeline to handle multiple views.
- A “Reproducibility checklist” section in the README (R version, packages, one-line command) would make this even cleaner.

## Overall Summary

Scientifically, the project is on-target and uses an appropriate morphometrics workflow. The main weaknesses in the original submission were *reproducibility and portability* (RStudio-only execution, hard-coded paths, and hard-coded result text). After refactoring into a standard `data/ / scripts/ / results/` layout and making the analysis runnable from the command line, the project meets the assignment’s automation goals and produces repeatable visual outputs.
